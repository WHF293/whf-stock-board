E2 · 数据与算法层

核心是一个纯函数：buildBoardRotation()。输入板块日历既有落库行，输出名次序列渲染模型；单测可直接对纯函数写，不碰 Vue。

// src/common/utils/build-board-rotation.ts（新增，一函数一文件）
export const buildBoardRotation = (
  dailyRows,      // BoardDailyRow[]（范围内，含回补日）
  limitRows,      // BoardLimitStock[]（范围内涨停明细）
  dates,          // string[] 交易日升序
  options,        // { topN, minLimitUp, maxLanes }
) => {
  // 1. 每日候选：板块涨停家数 ≥ minLimitUp，按 (limitUp desc, score desc) 取前 topN
  // 2. 段构建：日期升序扫描，同 boardCode 连续在榜 → 延段；掉榜即断段
  // 3. 名次序列：段内每日名次 = 候选排序位，掉榜日记 null（bump 线在此断开，connectNulls=false）
  // 4. 每段每日龙头：该板块涨停股 limitStreak 最大（并列取 sealTime 最早）
  // 5. 主线标签：当日 Top1 limitUp ≥ MAINLINE_MIN_LIMIT_UP(5) → 主线，否则无主线
  return { days, segments, lanes, marketByDate }
  //   days[i]     = { date, weekday, limitUpCnt, limitDownCnt, mainline }
  //   segments[k] = { boardCode, boardName, color, rankByDate[], leaders[], active }
  //   marketByDate = 申万一级 upCount/downCount 求和（dataLevel=1 才计入）
}
1零新增请求：三个输入全部来自板块日历既有 SQLite 表；回补日（dataLevel=0）只有涨跌停明细，图可画、上涨家数显「--」。
2并列与歧义：龙头并列取首封时间最早（与涨停池 fbt:asc 排序口径一致）；同板块当日被一级行业与热门板块同时命中时按 boardCode 区分，各自成线（数据层本就一对多）。
3性能：36 板块 × 400 日 ≈ 1.4 万行内存现算，毫秒级；「全部」范围下前端再做一次日期裁剪（默认仍取全部已定稿交易日）。
4常量落位：ROTATION_TOP_N(5) / ROTATION_MIN_LIMIT_UP(2) / ROTATION_MAINLINE_MIN(5) / ROTATION_PALETTE(6 色) 全进 constants，禁止散落字面量。
APPENDIX

口径定论与边界条件

  1. 题材口径定论：v1 复用现有 36 板块池（31 申万一级 + 半导体/航天航空/机器人/光伏设备/新能源）。申万一级是完整划分，横向求和可得全市场家数；题材敏感度弱于东财概念池是已知取舍，扩池走「手动白名单概念板块」路线，另行立项。
  2. 「主线 / 无主线」定论：当日 Top1 板块涨停 ≥ ROTATION_MAINLINE_MIN(5) 家判主线；节前缩量日（全市场涨停 < 60）强制判无主线并注「缩量」。
  3. 断段定论：掉榜一天即断段，不做「隔日接续合并」——参考 App 的轮动语义是断线即换挡，合并会让轮动节奏失真。同板块新段新色。
  4. 未定稿数据：当日盘中行参与渲染但主线判定/chip 标注「盘中」，收盘定稿后自动修正（复用既有 is_final 机制）。
  5. 边界：① 范围内全部为回补日（无涨跌家数）→ 主线判定退化为「涨停家数 Top1」且无主线标签全部显示但注「弱口径」；② 同一交易日一个板块涨停 0 家但得分率高 → 不上榜（阈值过滤）；③ 同日上榜板块数 > TopN → 只画前 TopN 名，落榜段在当日自然断线。
  6. 埋点定论：无埋点表。个人应用无埋点体系，页面加载/跳转行为由既有 weblog 采集覆盖。
  7. 不做（本期）：移动端适配、东财概念板块扩池、人工改判主线、题材间连线（接力箭头）。均列为 v2 候选。
常量默认值说明
